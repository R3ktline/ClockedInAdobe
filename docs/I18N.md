# Storefront language by visitor IP

The storefront speaks the visitor's language. The server reads the request, decides on a language
before the first byte of HTML, and renders that language directly — there is no English flash and
no client-side string swap after hydration.

## How the language is chosen

First match wins:

| # | Signal | Example | Source label |
|---|---|---|---|
| 1 | `babel.lang` cookie | the shopper picked a language in the header | `chosen` |
| 2 | `babel.demo-ip` cookie | the demo picker simulated a visitor abroad | `demo-ip` |
| 3 | CDN country header | `x-vercel-ip-country: DE`, `cf-ipcountry: FR`, `x-country-code` | `header-country` |
| 4 | the request's public IP | a local demo sends `X-Forwarded-For: 86.120.44.1` | `request-ip` |
| 5 | optional external lookup | `BABEL_IP_LOOKUP=1` | `lookup` |
| 6 | English | nothing matched, or the IP is loopback/private | `default` |

A country header always wins over guessing from the IP. Loopback (`127.0.0.1`), private ranges
(`10/8`, `172.16/12`, `192.168/16`) and link-local addresses never map to a language.

## Languages and countries

| Language | Code | Native name | Countries |
|---|---|---|---|
| English | `en` | English | fallback; also GB, IE, US, CA, AU, NZ, … |
| Romanian | `ro` | Română | RO, MD |
| German | `de` | Deutsch | DE, AT, CH, LI, LU |
| French | `fr` | Français | FR, BE, MC |
| Spanish | `es` | Español | ES, MX, AR, CO, CL, PE, UY, VE |
| Italian | `it` | Italiano | IT, SM, VA |

Numbers, prices and product facts do not change with the language: prices stay in RON from the
catalog, product copy stays exactly what the merchant wrote. Only the storefront's own chrome is
translated (see **Scope**).

## Trying it (demo)

Open any store page and use the globe button in the header (`EN`/`RO`/…) → **Simulated IP (demo)**:

| Pick | IP | Country | Language |
|---|---|---|---|
| Romania | `86.120.10.20` | RO | Română |
| Germany | `91.64.20.30` | DE | Deutsch |
| France | `92.184.30.40` | FR | Français |
| Spain | `88.0.40.50` | ES | Español |
| Italy | `151.0.50.60` | IT | Italiano |
| United States | `8.8.8.8` | US | English |

The picker writes `babel.demo-ip` and reloads; the server resolves the new language and renders it.
Choosing a language in the same panel writes `babel.lang` instead and overrides the IP.

Without the picker you can also drive it from the request headers, e.g.
`curl -H "X-Forwarded-For: 91.64.20.30" http://localhost:3000/taraba`.

`GET /api/locale` returns the current resolution, which is handy for checking a setup:

```json
{ "lang": "de", "country": "DE", "ip": "91.64.20.30", "demoIp": "91.64.20.30", "source": "demo-ip" }
```

## Scope

Translated (shopper-facing): header and category navigation, search, home hero, product page
(buy box, policies, specs, reviews chrome), listings and filters, cart, checkout, Babel's chat box,
the "What changed" card, the "Why this view?" dialog and the page-view pager. Block names in the
change card are translated too.

Deliberately **not** translated: product names, descriptions, specs, review text and review
summaries (catalog facts), merchant/lab/debug panels, the simulation lab, prompts and API traces.
The Director's `rationale` for a view is generated by the model in English and is shown as written.

## Privacy

The IP is read once per request to choose a language and then discarded. It is **not** written to
disk, attached to a visit, or logged. Only the shopper's own choice is remembered, in the
`babel.lang` cookie (one year, `SameSite=Lax`). The demo picker stores only the simulated address it
was given, and the "Automatic" option clears it.

No geolocation beyond country is requested, and the optional lookup is off by default. When enabled
with `BABEL_IP_LOOKUP=1`, the address is sent to `BABEL_IP_LOOKUP_URL` (default
`https://ipapi.co/{ip}/country/`) and the country is cached in memory for six hours; only the
country is kept.

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `BABEL_IP_LOOKUP` | unset | `1` enables an external country lookup for IPs the demo table does not know |
| `BABEL_IP_LOOKUP_URL` | `https://ipapi.co/{ip}/country/` | endpoint template; `{ip}` is replaced |

On Vercel, `x-vercel-ip-country` is present automatically. Behind Cloudflare, `cf-ipcountry` is.

## Files

- `lib/i18n/locales.ts` — languages, country map, demo IP table.
- `lib/i18n/geo.ts` — header parsing, private-IP rules, resolution order, optional lookup.
- `lib/i18n/server.ts` — `localeFromRequest()` for server components.
- `lib/i18n/dictionaries.ts` — the strings and `translate()` (English is the fallback).
- `lib/i18n/I18nProvider.tsx` — client context and `useI18n()`.
- `lib/i18n/LanguageSwitch.tsx` — the header control and demo IP picker.
- `app/api/locale/route.ts` — read/set the language cookies.
- `lib/i18n/i18n.test.ts` — country/IP/resolution tests and dictionary completeness.

Adding a language: add it to `LANGS`, add its country codes to `COUNTRY_LANG`, and add a full
dictionary. The test fails if any key is missing.
